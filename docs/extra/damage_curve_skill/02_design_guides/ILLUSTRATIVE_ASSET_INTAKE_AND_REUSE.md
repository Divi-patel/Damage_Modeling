# From an illustrative asset to researchable responses

Use when a new asset family, detailed twin or anatomy export introduces scope and response-grain questions.
For a bounded update to a well-defined existing cell, reuse its established scope and skip unnecessary
intake. This guide precedes cell naming and numerical fitting; it creates no required runtime fields.

## 0. Preserve the illustrative view

An idealistic diagram, table or interactive twin helps reveal the physical boundary, systems, components,
locations and possible mechanisms. Preserve the source/version/hash and relevant node IDs. Distinguish
observed facts, source-backed class information, declared assumptions, illustration-only values and unknowns.
An elaborate tree, hazard rating, sample threshold or illustrative loss is not a calibrated curve.

Use the twin already supplied when adequate. Creating a new visual or exhaustive parts tree is not a
prerequisite for every curve update. Do not convert sample design or insurance values into physical truth.

## 1. Separate the profile from response and release identity

Define the physical asset and intended loss scope before selecting its response. Keep category/use,
construction, geometry, condition, fixed systems and value boundary distinct. Let each method identify
which attributes act as selectors, event conditioners, coupling inputs or value quantities.

A new profile does not automatically require a new curve implementation or cell. Several compatible
profiles can bind the same admitted response; one profile can use several responses. Cell boundaries
still own capability and release. Do not assign production codes from illustration node labels.

## 2. Choose the smallest defensible response grain

Map displayed nodes to mechanism-specific failure units or qualified source-native assemblies. Split
when a material difference in failure, demand/exposure, repair consequence or useful intervention is
supported by evidence. Merge where the source supports an assembly and no justified split exists.
Preserve value and an explicit response gap when a material unit is unsupported.

More anatomy does not require more curves. A source-native assembly is not automatically whole-asset
coverage; qualify its physical/economic boundary. Never partition its numerical curve into independent
component curves by arbitrary cost shares, or add an assembly and its included component losses twice.

## 3. Inspect reusable inventory before deriving new behavior

Inside this repo, follow [the shared-component substrate standard](../../../method/standards/20_shared_component_substrate_standard.md)
and inspect the relevant `docs/method/shared_components/` references and exact current cell artifacts.
Outside the repo, use that standard from the supplied package when available; otherwise record the missing
authority and keep the result a research candidate. The summary here does not authorize runtime promotion.

Record whether reuse is definition, axis, evidence, candidate curve or explicitly runtime-approved.
Test equipment/construction, mechanism, axis/unit/datum/support/range, ordinate/repair denominator,
selectors, event conditioners and transferable evidence endpoint. Match all load-bearing dimensions or
record a sourced bridge/variant. A common occupancy, component name or identical parameter list is insufficient.

Keep intrinsic response identity separate from local presence, geometry/exposure, value, ownership,
support allocation and capability. Reference an existing shared candidate where justified; do not create
a competing registry. Non-runtime candidates cannot populate output-bearing bundles. Independently
adopted cell-local assumptions require their own evidence/tier/decision and may be compared for equality.

The standard requires at least two proven compatible cells and a separately governed contract/consumer
migration before shared runtime promotion. Until then, preserve self-contained admitted cell artifacts.
A shared source or candidate change must not silently update an already pinned cell.

## 4. Declare units and value before curve search

Record the response denominator, currency/price basis and cost scope. Choose the appropriate quantity:
item count, area of a specified surface, capacity, total budget or share. A floor-area unit is not a
roof-area unit, and a building needs no fictitious capacity field. Keep market value, insured limits,
physical repair/replacement, contents and business interruption distinct.

Use the [value crosswalk](VALUE_CROSSWALK_GUIDE.md) for every material source row. Keep omitted response
coverage visible in the full declared value boundary; do not renormalize supported components to 100%.

## 5. Agree the consumer interface and research disposition

With Hazard, state the pathway/demand, units, height/datum/duration, geometry and affected-unit meaning,
response endpoint/denominator, allowed bridges, valid domain, uncertainty and missing-input behavior.
Assign each transformation once. Damage owns vulnerability; Hazard owns occurrence, coupling and annual
composition. Research both sides in parallel against that interface.

Use the [intake worksheet](../templates/TEMPLATE_ASSET_INTAKE_AND_REUSE.md) in the existing discussion or
scope dossier; link existing source/claim/value registers instead of duplicating them. Record unresolved
owner choices separately from discoverable scientific/engineering facts. Then continue the new-cell or
existing-cell workflow. If no response qualifies, narrowing scope or withholding is a valid result.

## Reasoning checks

### Make the reuse decision reviewable

Use one progress table in the existing intake/discussion, linking the authoritative dossiers and registers:
**dimension → source requirement → target fact → evidence → disposition → owner/next action**.
Distinguish completed numerical reproduction from physical applicability, value binding and permission to
use annual metrics. Equal numbers or a passing evaluator do not establish the other three.

Pin the source artifact, capability, evaluator and target profile/value inputs. If a fresh source request
fails, distinguish retained governed evidence from newly inspected primary evidence. Record the attempted
URL/date/result and precise unverified claim. A retrieval failure does not erase prior qualification; nor
does inherited qualification prove a new target matches. Avoid restarting a broad search when a specific
footnote, denominator or transfer question is the remaining gap.

Give the owner a concrete source-to-target comparison before asking about a consequential proxy or narrower
product. Do discoverable research first; never treat agreement to investigate as approval of release or of
an unresolved denominator. Keep review receipts outside output-bearing cell bundles until admission.

| Scenario | Expected treatment |
|---|---|
| Warehouse and office have the same qualified roof assembly but different areas | Consider one intrinsic response; bind geometry, exposed value and other units separately |
| Their roof covers match but deck/attachments or demand basis do not | No automatic numeric transfer; reuse only supported vocabulary/evidence until qualified |
| A house source includes contents or loss of use | Separate the endpoint; do not apply that total to a building-only repair budget |
| Office has multiple floors but twin only supplies retail details | Identify missing office inputs; do not relabel the retail profile |
| A whole-building flood table overlaps fixed-services/interior values | Preserve assembly scope and exclusivity; do not add included unit losses |
| A shared candidate has matching numbers but is non-runtime | No loader fallback or implied release; maintain cell-specific admission |
| Existing Solar/Wind task has settled failure units and $/MW units | Retain its scope and units; no building intake or schema migration is forced |
