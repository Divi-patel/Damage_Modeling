# Decision log — flood_real_estate model v0.1 / docs r1

All entries are **proposed** on 2026-10-11 by JL for this scaffold. None is owner-accepted yet. Items marked
*owner* need the reviewer (or the platform) before they can be settled.

| ID | Decision | Reason | Alternatives considered | Revisit trigger |
|---|---|---|---|---|
| D-FRE-01 | One cell, `flood_real_estate`, for all three asset types. The reference building is a selector on one failure unit. | Same mechanism, axis, source libraries and denominator across the three types. Real estate is one asset category (doc 06). Mirrors `hail_solar` archetype selectors. | Three cells (`flood_residential`, `flood_commercial`, `flood_industrial`). | A type needs a different mechanism, axis, or value boundary. |
| D-FRE-02 | Model the structure only, as a fraction of **replacement cost new**. Land, contents, depreciation and market value are excluded. | The Hazus and NACCS ordinates are % of structure replacement value; the denominator must match. | Market or assessed value; depreciated value. | Owner chooses a different reporting basis (then convert explicitly, never silently). |
| D-FRE-03 | One whole-building curve per reference building for flood v0.1/v1. | The sourced curves are whole-building. Doc 06 accepts this as a deliberate v1 exception. Precedent: `flood_wind` whole-substation atom. | Component split (structure / roof / walls / services). | A component-level flood source is curated. |
| D-FRE-04 | One still-water pathway, `flood_inundation_contact`, for riverine, pluvial and coastal water. | Same physical mechanism. `flood_solar` and `flood_wind` do not split by flood source; the pathway-splitting guide separates mechanisms, not peril names. | Separate coastal pathway. | Coastal water needs a different axis or mechanism (see D-FRE-06). |
| D-FRE-05 | Water type is an event-time conditioner: freshwater → Hazus default (Table 5-2); coastal surge → NACCS 2015; unknown → withhold. | The two libraries were built for different water and settings. Unknown withholds rather than guessing, as `flood_wind` does for salt or unknown water. | One library for all water; default unknown to Hazus. | Hazard cannot supply water type; or a single national library is adopted. |
| D-FRE-06 | Declare `flood_wave_velocity` (wave impact, fast-moving water, scour) as a separate pathway, **deferred**: no curve in v0.1, and wave damage is withheld, not zero. | (1) Different mechanism: force and undermining rather than soaking. (2) Different input: wave height or flow speed, not still-water depth. (3) Strongly site-dependent: exposure to open water, foundation and soil. (4) Hazard's coastal grid supplies surge depth (SLOSH), not wave heights or flow speeds, so a wave curve would have no input. (5) Mixing it into the still-water curve would double-count once a wave pathway exists, and would overstate sheltered coastal flooding (FRE-C021). Follows `flood_wind` D-FW-07 / FW-C012 (scour and wave loading excluded, foundation withheld not zero). `flood_solar` instead carries a T4 scour placeholder (FS_FOUND); not copied. | Fold wave damage into the coastal curve (e.g. FEMA DF 658); add a T4 placeholder like `flood_solar` FS_FOUND. | Hazard supplies wave height or flow speed, and coastal wave or velocity curves (e.g. NACCS wave tables, FEMA BCAR coastal curves) are curated. |
| D-FRE-07 | Axis = depth above first finished floor, in ft; outside the published range withholds. | This is the native axis of both libraries. It makes first-floor height an explicit input, so elevation measures later become a parameter change (the reviewer's ask, 2026-10-05). | Depth above grade with a baked-in floor height. | — |
| D-FRE-08 | Choose candidate curves by the **Hazus default per occupancy (Table 5-2)**, not by picking among class-specific curves. | Class curves for one occupancy disagree widely (warehouse structure curves range 1%–62% at 4 ft). The defaults are Hazus's own averages across classes, which makes the choice defensible. | Hand-pick class curves; New Orleans salt/fresh-water curves. | Validation (e.g. NFIP claims) shows a default is biased for our reference building. |
| D-FRE-09 | Building subsystem and component names (`BUILDING`, `BUILDING_STRUCTURE_ASSEMBLY`, `CONTENTS`) are proposals. *Owner: platform / reviewer.* | The platform vocabulary has no building subsystem. Standard 24 requires an exact code join. | Reuse `CIVIL_INFRA`. | Platform codes are issued. |
| D-FRE-10 | Platform type labels (Hotel → Commercial, Warehouse → Industrial) do not affect the curve; the curve keys on the recorded Hazus occupancy. *Owner: reviewer with stakeholders (doc 06 check 4).* | The labels decide routing on the platform, not vulnerability. | — | Labels change. |
| D-FRE-11 | The legacy `Real Estate_Hail` array is not evidence for this or any future real-estate cell. | It was rejected in `hail_wind` as a mislabelled, unit-inconsistent array. | — | — |
| D-FRE-12 | Contents are deferred as a separate failure unit, not folded into the structure ratio. | A different value bucket and different Hazus curves; folding them in would mix denominators. | Include contents in v1. | Owner asks for contents. |
| D-FRE-13 | Use only the ten NACCS depths the report publishes (−1 to 10 ft). Never use the compiled values at 4, 6, 8 and 9 ft. | Step 3 found those values are fills that repeat the previous knot and understate damage (FRE-C006). | Use the compiled table as is (as the Plymouth trial did). | — |
| D-FRE-14 | Coastal curve for the commercial reference building is NACCS `COM-ENG`; the warehouse uses `COM-PRE`. | Prototype descriptions: Prototype 2 is a steel-framed engineered building; Prototype 3 is a one-story steel or light-metal building (FRE-C008). | `COM-PRE` for both. | The commercial reference building is defined as masonry or wood. |
| D-FRE-15 | **Superseded by D-FRE-22.** First-floor-height defaults come from the NACCS most-likely prototypes: house 1 ft, warehouse 1 ft, engineered commercial 0 ft. | Sourced, and the prototypes match the reference buildings. They replace the unsourced estimates in the draft reply. | NSI defaults; ad hoc estimates. | NSI check (FRE-S009) disagrees materially. |
| D-FRE-16 | Commercial freshwater curve = Hazus DF 217 (COM1, average of 47 retail classes). Office (DF 431) becomes a later commercial profile. | One occupancy per reference building keeps curve and value basis consistent; retail is listed first in the reviewer's definition and DF 217 is the broadest average (pressure test §2A). | DF 431 (office); averaging the two (rejected: creates a curve no source publishes). | Owner selects office, or NFIP comparison shows bias. |
| D-FRE-17 | Warehouse freshwater curve = Hazus DF 341 (COM2, average of 22 wholesale/warehouse classes). Light industrial (DF 559) becomes a later industrial profile. | The reference building is a warehouse; Hazus files warehouses under COM2 (pressure test §2B). | DF 559 (light industrial). | Owner selects light industrial, or NFIP comparison shows bias. |
| D-FRE-18 | Coastal surge keeps NACCS for all three buildings, with the North Atlantic and house low-bias limits stated. FEMA's coastal defaults (DF 658 for the house; riverine curves for commercial) are the recorded alternative. | Only verified source with coastal curves for all three buildings; keeps wave effects in the deferred wave pathway (pressure test §2C). | FEMA coastal defaults; Hazus for all water. | Owner selects FEMA defaults, DF 658 ordinates are curated, or NFIP comparison. |
| D-FRE-19 | Freshwater and coastal libraries are never blended or averaged, and no uplift is applied to close the gap between them. | At 4 ft they differ in both directions (pressure test §3); an unreviewed factor would be a second, unversioned model. | Uplift the Galveston curves to NACCS; average the two. | NFIP claims comparison. |
| D-FRE-20 | Values between published depths use **straight lines between the published points** for all six records and the NACCS bounds. | Reproduces every published value; matches FEMA's own practice of interpolating between the 1-ft points of the Hazus library (Hazus 6.1 TM §7.4, §8.4.1; NACCS gives no rule); on all six point curves the best smooth fit predicts held-out points worse and moves published values by 2–5 points; the Plymouth catalogue's own 10% rule picks no smooth fit for any point curve; cells built on published tables (`flood_solar`, `flood_wind`, `wildfire_solar`, `wildfire_wind`) use straight lines, while smooth forms are used where curves are derived (hail, wind) (curve form decision §2). | Best smooth fit per curve (Plymouth v0.4); PCHIP (0.2–0.5 points better on four curves). | A reviewed reason to prefer smoothness, or curves whose published points are too sparse for straight lines. |
| D-FRE-21 | Below the lowest published depth the result is 0% (every record is already 0% there); above the highest published depth (Hazus 24 ft, NACCS 10 ft) the result is withheld, with no extrapolation or clamp. | The sources record no damage below their range and publish nothing above it; follows `flood_wind`'s range policy. | Hold the last value flat above the range; extrapolate. | A source publishes deeper ordinates. |
| D-FRE-22 | First-floor heights are the NSI 2026 defaults: house 0.75 ft (documented), commercial 0.25 ft and warehouse 0.25 ft (read from NSI records, T3). One height per building, used for both water types; no Hazus-style rounding. | National, current and survey-based (FRE-C022, C023); the NACCS values describe North Atlantic prototypes. Supersedes D-FRE-15, written before the NSI 2026 documentation was read. Warehouse is most sensitive (coastal damage at 2 ft above grade 20% → 26%). | NACCS prototype heights (1 / 0 / 1 ft); NSI 2022 (0.5 ft house); Hazus whole-foot rounding. | NSI documents non-residential defaults, or owner chooses otherwise. |
| D-FRE-23 | The structure failure unit carries 100% of structure replacement cost new; NSI `val_struct` (depreciated) is rejected; the per-area cost source stays open, and scenario dollars stay withheld until it is chosen. | Matches the curve denominator (FRE-C001, C024). Four options documented without a selection (reference buildings §4). | Select NSI `fullrep` now; use team reference values. | Owner selects a per-area source. |
| D-FRE-24 | When depth is given above grade, a depth of 0 or less means the building is not inundated and returns 0%, even where the curve has damage below the floor. | FEMA DF 129 reads 3% at −1 ft and 13% at the floor, so a dry slab house (floor 0.75 ft) would otherwise show about 5.5%. Hazus only estimates damage where the flood depth at the structure is above zero. | Evaluate the curve below the floor for dry buildings. | A source shows damage without water above ground (e.g. groundwater seepage) is in scope. |
| D-FRE-25 | Package choices for v0.1: NACCS Min/Max kept as separate bound records emitted with the point value (`scalar_mean_plus_bounds`, a non-probabilistic building-variant envelope); water type stays a conditioner and record routing is declared in `record_routing_fields`; the reference first-floor heights are carried in the pathway for the depth-above-grade mode. | Keeps the method semantics (water type is event-time state, D-FRE-05) and the full NACCS publication; consumer integration gaps are recorded in the validation report §4 rather than worked around. | Drop the bounds; make water type a selector to fit the current Hazard loader. | Consumer cutover design. |
