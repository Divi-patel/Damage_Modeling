# Decision log — tropical_cyclone_wind_real_estate model v0.1 / docs r1

All entries are **proposed** on 2026-10-12 for JL's decision. None is accepted yet. Entries marked **OPEN** list
options without a proposal, because they depend on what step 3 finds in the source.

| ID | Decision | Reason | Alternatives considered | Revisit trigger |
|---|---|---|---|---|
| D-TCRE-01 | One cell, `tropical_cyclone_wind_real_estate`, for all three asset types; the reference building is a selector on one failure unit. | Same mechanism, axis, source library and denominator across the three types. The name follows the sibling cells `tropical_cyclone_wind_solar` / `_wind`, so hurricane, typhoon and tropical storm share one address. Mirrors `flood_real_estate` D-FRE-01. | `hurricane_wind_real_estate`; three cells by type. | A type needs a different mechanism, axis or value boundary. |
| D-TCRE-02 | Reuse the three `flood_real_estate` reference buildings with identical IDs and attributes; add only wind-specific attributes (D-TCRE-07). | A building priced by both cells must be the same building, so the losses can be compared and combined. | Separate wind reference buildings. | `flood_real_estate` changes a reference building. |
| D-TCRE-03 | Axis = peak 3-second gust at 10 m, open terrain, in mph (`tc_peak_gust_3s_10m_mph`). Saffir-Simpson category and one-minute or ten-minute sustained wind are rejected as inputs. Damage applies no averaging-period, height or terrain bridge. | It is what Hazard delivers (3-s gust, 10 m, mph, Exposure C) and, subject to step-3 verification, the native axis of the Hazus functions. Same gust basis as `tropical_cyclone_wind_wind`; the unit is mph instead of km/h to match Hazard and Hazus without a conversion. | km/h or m/s; sustained wind with an internal gust factor (would repeat Hazard's bridge). | Step 3 finds the Hazus axis is not open-terrain 3-s gust; Hazard changes its delivered field. |
| D-TCRE-04 | One pathway, `tropical_cyclone_wind`, that **includes** the windborne-debris and rain-ingress damage embedded in the source loss functions. No separate debris or rain-ingress pathway may be added while records are Hazus-based. | Hazus simulates pressure, missile impact and water entry through breaches in one building model and publishes one loss ratio (to verify). They cannot be separated without component-level output. Adding them separately would count the same damage twice. This deliberately differs from the sibling cells, whose wind-loading-only sources exclude them. | Wind pressure only (no source separates it); separate debris and rain pathways (no source). | A source publishes separable component or mechanism losses. |
| D-TCRE-05 | Grain = one source-native whole-building record per reference building (and wind-characteristic combination). No separate roof failure unit in v0.1 unless step 3 finds a source that supports one. Roof attributes enter as selectors. | The Hazus loss function is whole-building (to verify). Doc 06 asks to split the roof "where the sources support it". Precedent: `flood_real_estate` D-FRE-03, `flood_wind` whole-substation atom. | Roof / envelope / interior split from Hazus damage-state definitions (would invent costs). | A component-level wind source is curated. |
| D-TCRE-06 | **OPEN — terrain.** Hazus functions differ by surface roughness (open to wooded), which changes the local wind and the debris. Hazard delivers open-terrain gust with no roughness. Options: (a) fix one reference terrain per building (e.g. suburban) as a stated assumption; (b) make terrain a required site input from Hazard (e.g. from land cover), withholding when unknown; (c) open terrain for all, as the most conservative and simplest. Terrain must be applied once only. | Decision depends on how Hazus indexes the gust (open-terrain gust with terrain as a building attribute, or local gust) — step 3. | — | Step 3 result; Hazard adds a roughness field. |
| D-TCRE-07 | **OPEN — wind building characteristics.** Fixed by the reference building: roof cover (shingle / membrane / metal), no opening protection. Not fixed: roof shape, secondary water resistance, roof-deck attachment, roof-to-wall connection, garage door, and type-specific fields. Options: (a) fix each to a stated typical value; (b) use Hazus's default regional/age mix and average the curves; (c) fix the ones resiliency measures change and mix the rest. | Explicit values make a future measure (shutters, straps, roof deck) a one-field change; a mix is closer to "typical" but hides the attribute. Step 3 reads which fields each type has and what Hazus defaults are. | — | Step 3 result. |
| D-TCRE-08 | Out of scope: storm surge, waves and rainfall flooding (→ `flood_real_estate`); TC-spawned tornadoes (→ a future convective-wind × real-estate cell); contents, loss of use, BI (deferred; Hazus publishes contents and loss-of-use functions). | Matches Hazard's sub-peril routing (surge → Flood Coastal, rainfall → Flood Pluvial) and the sibling cells' boundaries; doc 06 "building (structure) damage first". | Fold surge or contents into this cell. | Owner adds contents for real estate. |
| D-TCRE-09 | Denominator = structure replacement cost new, 100% on the one failure unit, shared with `flood_real_estate`; the per-area cost stays the shared open seam and scenario dollars stay withheld. | One building, one value basis across perils. Hazus building loss ratio is relative to building replacement value (to verify). | Market, assessed or depreciated value. | JL selects a per-area source (applies to both cells). |
| D-TCRE-10 | The legacy `hurricane_tropical_cyclone_wind_storm_residential` ("Climada") and `strong_wind_small_residential` arrays are not evidence for this cell. | No averaging period, height, terrain or building type; unexplained 37% saturation; the second is straight-line wind (coverage note §2). | Use as a cross-check. | — |
| D-TCRE-11 | Wind and flood losses on the same building for one storm are combined by the consumer, which must keep the total at or below 100% of structure value. This cell records the rule; it does not implement it. | Two cells, one building; Hazard has no storm identity today, so the join cannot be built yet. Same `event_family_id` rule as the sibling cells. | Cap inside each cell (cannot see the other peril). | Hazard adds storm identity for wind and surge. |
| D-TCRE-12 | Outside the selected curves' published wind range the result is withheld (no clamp, no extrapolation); below the lowest published speed, the source's own zero is used only if the source states it. | Same range policy as `flood_real_estate` and `tropical_cyclone_wind_wind`. Hazard's 61–229 mph lies inside the likely Hazus range (about 50–250 mph, to verify). | Clamp to the last value. | Step 5 fixes exact ranges. |
